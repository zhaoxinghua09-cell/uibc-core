# 智能体身份码：我们读到哪里，为什么不往下读

对应 `GB/Z 185.2—2026《人工智能 智能体互联 第2部分：身份码》`，实现见 `uibc_core/agent_identity_code.py`，测试见 `tests/test_agent_identity_code.py`（27 条）。

## 1. 一句话

我们做**形状判定**，不做**真实判定**。合同的最高态是 `INCONCLUSIVE`，因为"这个码是真的"需要签发方与解析端点，而这两样都不在验证者手里。

## 2. 按条款实现的边界

| 条款 | 规定 | 我们的实现 |
|---|---|---|
| 5.1 | 五段点分；0-9/A-Z；字母不区分大小写；不留空格 | 线上为 8 段（4 段前缀 + 4 段）；小写归一化；空格/连字符拒绝 |
| 5.2 | 前缀固定 `1.2.156.3088` | 前缀不符即 `INVALID`，并回显实际前缀 |
| 5.3 | 版本 1 字符，范围 `1`..`Z`（35 个）；当前约定版本为 `1` | 版本不是 1 个字符 → `INVALID`；是保留值 → **`UNSUPPORTED`**（不是畸形，是本构建没有规则） |
| 5.4 | 注册服务方 1..6 字符 | 超长 → `INVALID` |
| 5.5 | 注册请求方 1..6 字符 | 超长 → `INVALID` |
| 5.6 | 自定义序列号由服务方定；建议本体 ≤9、实例 ≤10 字符 | 一段内合并计算，上限 19，且**写明这是推导值、不是标准印出来的数字** |
| 6(d) | 一个身份码只对应一个智能体 | `duplicates()` 只报告重复，不替调用方下结论 |

## 3. 我们明确不做的三件事

1. **不签发**。5.3/5.4 把分配权给"智能体身份注册服务方"，给验证者的没有。
2. **不算校验和**。见下节。
3. **不解析端点**。标准全文没有任何一条定义解析接口。

## 4. 一条写进代码的发现：第三方实现比标准多两级

公开 Rust crate `aipmc-basic`（MIT，crates.io，0.0.2，2026-10）把身份码读成**十段**：

```
1-4 前缀 1.2.156.3088 | 5 版本(1) | 6 服务方(1~6) | 7 请求方(1~6)
8 本体序列号(1~9) | 9 实例序列号(1~9，全0=本体) | 10 CRC(4 位 Base36)
```

它的 CRC 是 `CRC-16/CCITT-FALSE(前9段 ++ SALT)` 再 Base36。三处与国标不一致：

- **段数**：国标 5.1 的图是五段（序列号一段），它拆成两段并加一段校验；
- **校验码**：国标全文没有 CRC 这个字段；
- **实例序列号长度**：它用 1~9，国标 5.6 c 建议 1~10。

而且它的 `SALT`（`REGISTRY_DEFAULT_SALT`）不公开，所以**这个校验码第三方无法复算**。

我们的处理：`detect_profile()` 认出这是 `aip-acps` 读法并如实说明，`parse_agent_code()` 对它判 `INVALID`（因为按国标它多了一段），**理由写清"不是国标、盐值不公开、不复算"**。这是目前我们对"两套读法"唯一能给出的确定答案——不是猜哪种对，而是分别标明各自依据。

## 5. 为什么这仍然有价值

- 之前仓里 OID 代码是 **0 行**，对外只能说"我们知道它是什么"；现在能说"**已实现 GB/Z 185.2 的格式解析与校验**"，并有 27 条测试守着"不许冒充 `VERIFIED`"。
- 三处不一致（段数/CRC/实例长度）是**可复现的结构性差异**，任何做互操作的人都会撞上。我们先把它写清楚，而不是跟着第三方约定走。
- `UNSUPPORTED` 与 `INVALID` 分开，是我们七态词表第一次真正用在一个国标场景里：**保留值不是错误**。

## 6. 仍然缺的

1. **签发方**：拿到身份注册服务方分配的码（需走 CNOID 授权节点或电子标准院 AIP 社区）。
2. **解析接口**：至今无公开定义；若哪天出现，`INCONCLUSIVE` 才可能升到别的态。
3. **AIP 官方参考实现**的身份码模块是否与 `aipmc-basic` 一致——未核（AtomGit 仓未取）。
