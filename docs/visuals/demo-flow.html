Steps 7 and 8 are the pair a digest check cannot produce. A forgery that recomputes every hash and re-seals with its own key is internally consistent — so any content-addressed scheme will report it valid unless the verifier knows which key it expects. Pinning is what turns a PASS into a FAIL. Digests agree on bytes; they do not decide what to refuse.

What this demo does and does not establish

Establishes

  • tampering with recorded evidence is detected without any service, key or network
  • the same package verifies for an unrelated party who holds only the public seal
  • a full re-hash forgery is caught only when the verifier pins a key, and the tool says so instead of staying silent
  • assurance level is reported, not implied: integrity vs public-key vs pinned

Does not establish

  • that the owner is who the key claims — pinning is a trust decision made outside this demo
  • that any timestamp is anchored: the OpenTimestamps proof is still a pending calendar statement, not a Bitcoin block attestation
  • conformance to any external standard (AER-1, ASQAV, others)
  • that a verdict is correct in the world — only that recorded bytes did not change
