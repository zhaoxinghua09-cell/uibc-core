一句话结论

同一把尺子上（每维最多记 1、分母 5），本仓 5/5，取样内最好的一家 3/5；
剔掉取样内无人得分的维度后，是 3/3 对 3/3 —— 平手。
所以 「全面超越」在这张表里不成立。成立的只有一句：位级铺扫与「门自证」这两维，40 家里 0 家有可复跑的证据。

同尺对照（为什么不是 10 比 3）

为什么 10 比 3 不公平：竞品侧每维最高记 1、D5 在 score_one 里记死 0（分母 4）；本仓每维可记 2（分母 10）。把两个分母并排当标题，等于把「只有我们能拿到的两分」算成实力差。

我们不如人的地方（自认，带数字）

  • 代码体量 13,528 行；对方 33,880–323,393 行
  • 测试行数 29,147，中位 28,879——持平，不是领先
  • 没有任何活网集成测试（对方那条 networks.integration 是真在跑）

  • 版本史：0.4.2 从未出现在 pyproject.toml 的历史里

你自己复算：四条命令，四个期望输出

git clone --depth 1 https://github.com/zhaoxinghua09-cell/uibc-core && cd uibc-core
python tools/competitor_gate_parity.py --check   # PARITY OK: 40 repos, best 3/10, this 10/10
python tools/outsider_rerun.py --check           # OUTSIDER OK: 2474 files, 6af6d08d0dc7, e477e6dea005
python tools/refs_check.py --check               # REFS OK: 40 citations, 0 dead, 9 moved
python tools/stranger_own_check.py               # VERDICT: SELF-CONSISTENT (10 passed, 0 failed)

看板另开一个文件：docs/parity-board.html（41 行、3 张内联 SVG、0 处外链；断网打开图形仍在）。
关键：outsider_rerun.py --check 必须在带 .git 的克隆里跑。在没有 .git 的目录里，它只能证明「与磁盘一致」，证明不了「与提交一致」——这正是我们被自己的 CI 抓住过一次的地方。

证据落在哪三处

  • docs/COMPETITOR-GATE-PARITY.md —— 40 家同尺表、同尺复算段、谎报上限标定
  • docs/outsider-rerun-receipt.json —— 树摘要 / 内容摘要 / 4 步退出码 / 41 个测试
  • docs/refs-report.json —— 40 条引用逐条 200，9 条 301 已按新名复核

仓库（纯文本）：github.com/zhaoxinghua09-cell/uibc-core，main 034ffc1。
