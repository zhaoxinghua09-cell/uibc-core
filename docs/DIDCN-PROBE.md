## 6. One code, one agent (GB/Z 185.2-2026, clause 6 d)

The clause says one identity code may correspond to one agent only. It is the
only requirement in the standard an outsider can test, and only weakly. Two
things are checked, both necessary and neither sufficient:

- the published agent list must not carry the same code twice;
- resolving one code twice must return the same identifier.

```
python tools/probe_didcn_platform.py --uniqueness           # network, rewrites docs/didcn-uniqueness.json
python tools/probe_didcn_platform.py --check-uniqueness     # offline, fails on duplicates or drift
```

A pass means "holds as far as an outsider can see". It cannot rule out the
platform handing the same code to two agents that are not both published, and
the page says so rather than claiming conformance.

## What this supports, and what it does not

*10 of 10* invalid strings come back `200 + success:true + code:0`, with the failure only visible in `resolutionStatus=FAILED`; `vcVerificationStatus` is `SKIPPED` in *10 of 10*; the empty string is rejected with HTTP 400. A caller that branches on `success` or `code` records a failed resolution as a success.

It does **not** show the platform verifies signatures, and it does not show that any of this is wrong behaviour -- the platform may define `success` as "the request was understood". It shows only that the word a caller is most likely to branch on does not carry the verdict. Re-run it before quoting it: a service can change, and `--run` fails loudly when the observation no longer holds.
