# 我们的检查器跑 AER-1 的语料：结果与限界

> 这一页的作用是**把"更严"变成可复跑的证据**，而不是主张。命令一行，结果落盘，任何人都能重跑。

## 怎么跑（无依赖，标准库即可）

```bash
python tools/aer1_crosswalk.py
# -> tools/out/aer1_crosswalk.json
```

语料来源：`https://zambo.dev/aer1/corpus.json`（本地缓存 `tools/out/aer1_corpus_index.json`，15706 B）。

| 分类 | 类别数 | 已映射向量 | 已映射检查 |
|---|---|---|---|
| **COVERED**（我们有对等检查） | **33** | **57** | **57** |

其中 **77 条未映射向量全部是正向向量（`valid/*`）**——即"他们的 schema 下的合法用例"，我们没有对应检查。**这批不计入覆盖率**，否则数字会好看但没意义。

## 方法说明（为什么按类别而不是逐向量）

两边 schema 不同。强行逐向量跑，得到的大多是 schema mismatch，而不是"我们漏了什么"。所以映射按**语义类别**做：一个类别里只要我们的检查覆盖了该类别的判定意图，就记为 COVERED；只覆盖一半记 PARTIAL。

## 已知限界（写在结果里，不藏在附录）

1. **2026-11-17 更新：TO-ADD 已归零，且这个零是跑出来的**。`aer1_crosswalk.py` 现在对每个可关闭的类别挂一个**探针**——真拿恶意输入调验证器——探针拒绝才判 COVERED，代码退步就自动掉回 TO-ADD。当前 COVERED 33 类 / 57 向量 / 57 检查，**TO-ADD 0**，**PARTIAL 1 类**（Merkle：9 向量 / 12 检查，实现存在但默认构造与 §8.1 不同，见限界 2），N_A 8，未映射正向向量 77 条不计入比例。**禁止对外说"全面覆盖 AER-1"**：这是分类级映射，不是逐向量执行。
2. **Merkle 树与包含证明：实现存在，构造与 AER-1 不同**。我们的包含证明实现已在（负对照通过：错索引、错叶子均不通过）。2026-11-19 按 Brennan Zambo 的邀请把 AER-1 的 9 个 Merkle 向量实跑：其构造按 §8.1 复现 9/9 预期根，我们的默认构造 0/9——三处参数不同（域分隔前缀 0x00/0x01、奇数节点处理、空树根约定）。为把这层差异固定下来，`uibc_core/merkle.py` 加了一个**命名 profile `aer1`**（§8.1 三条参数逐条实现，默认构造一字未改）：同一份九向量在 `profile="aer1"` 下 9/9 通过，在默认 `rfc6962` 下仍 0/9。故 Merkle 类记为 **partial**：不是没有实现，是默认构造未对齐，一侧的根不能在另一侧默认地复验——要复验必须显式点名 profile。
3. **base64 严格性已实现**：pad-bit 必须为零、填充必填、非 base64 字节拒收——三项均由探针实时验证（见交叉表工具），不再列为缺口。
4. 这不是"我们通过/不通过他们的测试"——是**覆盖率映射**，不构成对 AER-1 一致性（conformance）的声明。

## 一句可以对外说的话（唯一版本）

> 我们按 AER-1 公开语料的类别做了交叉映射：33 类 / 57 项检查有对等能力（含严格 base64、anchor 事件解析），1 类部分覆盖（Merkle 包含证明：实现存在，AER-1 §8.1 构造可作为命名 profile `aer1` 复现其 9 个向量，默认构造不同），无缺口类别，77 条正向向量无对应。判定由探针实时重算，命令与结果公开，可复跑。

不加"我们更强"，也不加"他们没做"——这两句都不成立。
