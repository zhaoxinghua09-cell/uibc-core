Verify a UIBC evidence package — in your browser

The same checks as uibc verify 0.3.3 (S1–S18) and the same three-valued verdict: PASS, FAIL, or an honest INCONCLUSIVE. Since v1.1 the seal covers the lifecycle record too — truncating or rewriting the event chain now fails the seal check itself. Everything runs locally on this page — nothing is uploaded.

Honest limits · 诚实边界 — This page is a JavaScript port of the Python reference verifier (uibc-core 0.3.3). On a 27-case parity corpus — the pristine demo package, every tamper class, legacy v0.3 seals, HMAC seals with and without the key, Merkle / receipt-chain / anchor / policy packages — its verdicts agree with uibc verify check-for-check; the corpus and the harness ship in the repository (tests/verify_html_parity/). Both sides canonicalize with RFC 8785 JCS, so sealed JSON hashes identically on either side. Declared limits: an RFC 3161 timestamp token (S16) is reported INCONCLUSIVE on this page, never PASS — the port does not parse DER tokens; the Python verifier without its optional dependency does the same. HMAC seals can only be checked with the owner key; without one they are INCONCLUSIVE, never silently passed. JSON integers beyond 2^53 lose precision in JavaScript and will not verify. Timestamps are checked for form and consistency, not independently anchored. 本页是 Python 参考验证器（uibc-core 0.3.3）的 JavaScript 移植版；在一个 27 例对照集上（原样演示包、各类篡改、v0.3 旧封签、带/不带密钥的 HMAC 封签、Merkle／收据链／锚定／策略包），其裁决与 uibc verify 逐项一致，对照集与测试脚本随仓库发布。两侧均按 RFC 8785 JCS 规范化，封签 JSON 的哈希完全一致。明示边界：RFC 3161 时间戳令牌（S16）在本页只判 INCONCLUSIVE、绝不 PASS——本移植版不解析 DER 令牌；Python 验证器在缺少可选依赖时同样如此。HMAC 封签无所有者密钥时只能判 INCONCLUSIVE，绝不放行。超过 2^53 的 JSON 整数在 JavaScript 中会丢精度、无法通过验证。时间戳只查形式与一致性，未做独立锚定。
