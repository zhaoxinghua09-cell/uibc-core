## 入门档（P-01 ~ P-03）

**P-01 迁移判定协议入门** `[AI底稿→人工精修]`
- 背景：自治智能体 A 从 E1 迁移至 E2，判定边界部分失效。
- 任务：用 UIBC-MEM 完成一次**可验证的记忆迁移**：构造 Memory Package，
  迁移后通过四项 Preservation 校验（M2 事实/M3 来源/M4 引用/M5 版本）。
- 门禁：迁移前后的 memory_root 均可被 `verify` 复算；注入一条伪造记忆
  必须被检出。
- 交付物：memory package + 迁移脚本 + 验证报告。
- 评分点：四项 Preservation 全过（40）/ 注入检出（30）/ 报告含 scope
  与 limitations（30）。

**P-02 知识库过期告警** `[AI底稿]`
- 背景：医疗合规智能体部署到新 jurisdiction，原知识库过期。
- 任务：构建迁移问责机制：知识冲突自动告警并暂停决策，记录冲突点与责任人。
- 约束：告警不可绕过、责任链不可删改、支持离线回放。
- 评分点：冲突召回率 / 责任链不可篡改性（用 evidence root 复算）/ 回放完整性。

**P-03 仿真→实车判定漂移** `[AI底稿]`
- 任务：量化判定一致性并对漂移动作做责任归属（训练数据/部署配置）。
- 评分点：度量合理性 / 归因可解释性 / 离线可复现（提交 `.uibc` 包）。

## 进阶档（P-04 ~ P-05）

**P-04 攻击者视角：Break the Seal** `[人工精修 · 2026-11-12 按 v0.3.0 重写]`
- 背景变化（先说清）：本题的 v0.2 版前提已被 v0.3.0 修复——旧攻击
  （改证据、重算哈希根、无封签）在开放模式下曾判 PASS；v0.3.0 起
  同一包判 **INCONCLUSIVE**（未决不再洗成 PASS）；换钥攻击在不钉扎时
  对攻击者自己的钥匙验得过（封签对自签自洽），**钉扎业主公钥即 FAIL**
  （`uibc demo` 第 7/8 步可亲手复现）。
- 任务（三段）：① 逐格说明 24 格夹具矩阵中因三值语义改变的三格，
  以及为什么改的是这三格；② 在**钉扎业主公钥**的验证下，尝试构造
  任何能判 PASS 的伪造包——目前已知构造为零；若你构造成功，这是一
  条 critical 发现，按 INCENTIVES.md 记名并回流 fixtures；③ 对开放
  （不钉扎）模式给出一条可落地的加固，并说明它把哪一格的判定从
  INCONCLUSIVE 推向 FAIL、代价是什么。
- 评分点：矩阵归因正确性（40）/ 构造尝试的真实性与完整性（30，
  附可复跑脚本，跑不通不计分）/ 加固方案与语义文档的一致性（30）。

## 挑战档（P-06 ~ P-07）

**P-06 离线迁移问责协议** `[AI底稿→人工精修]`
- 任务：设计完整"迁移判定与问责"协议：判定失效识别（对应 gate HOLD）、
  高危动作冻结（对应 gate DENY + 撤销验签）、人类问责接口上报（对应
  dispute 登记，registry/disputes.jsonl 格式）。
- 约束：不得依赖云端、不得静默失败（对应报告纪律：scope/limitations/
  checked/not_checked 四段必备）、问责记录可审计（对应 evidence root）。
- 交付物：协议 spec + 参考实现 + 测试用例（全部以 `.uibc` 包提交）。
- 评分点：见 RUBRIC.md。

**P-07 撤销与争议的边界** `[人工精修]`
- 任务：实现一个最小撤销系统：撤销条目签名有效才阻断（Revocation），
  争议只标记不拦截（Dispute），并构造 3 个攻击用例试图让"争议"伪装成
  "撤销"阻断正常包、或让无效签名撤销被放行。
- 评分点：边界实现正确性（40）/ 攻击用例质量（40）/ 语义阐述——
  Dispute≠Revocation（20）。
